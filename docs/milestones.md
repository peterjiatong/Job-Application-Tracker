# 开发清单

配套文档：[需求分析与技术选型](./requirements-and-tech-selection.md)。

用法：从上往下一条一条做，做完并通过"验收"再勾选。每条控制在 0.5–3 小时。括号里是粗估工时，合计约 49 小时。

WXT 的具体 API 名称和命令以动手时的官方文档（wxt.dev）为准，本清单里提到的名称只用于指路。

---

## M1 核心闭环：识别、记录、提醒（约 17 小时）

做完 M1 就可以在 Chrome 里自用。

- [x] **M1.1 脚手架跑起来**（1h）
  - 做：用 WXT 的 React 模板初始化项目；`git init`；加 MIT `LICENSE`；启动开发模式，在 Chrome 里看到模板自带的 popup
  - 验收：改一行 popup 文案，浏览器里自动更新
  - 留意：弄清 `entrypoints/` 下每个文件对应扩展的哪一部分（content script / background / popup），后面全靠这个约定

- [x] **M1.2 类型定义与 URL 规范化**（1h）
  - 做：`lib/types.ts` 写 `JobRecord` 类型（字段见需求文档 1.7）；`lib/ats.ts` 里先写 `normalizeUrl(url)`：去掉 `utm_*`、`gh_src`、`source`、`lever-source` 等追踪参数和 `#` 片段；配好 Vitest
  - 验收：`pnpm test` 通过，至少覆盖"带追踪参数""不带参数""非法 URL 不抛异常"三种情况

- [x] **M1.3 解析器：Greenhouse 和 Lever**（1.5h）
  - 做：实现 `parseJobUrl(url)`，返回 `{ ats, company, jobId }` 或 `null`。结构做成"每个 ATS 一条规则"的表，先只填这两家
  - 验收：每家至少 4 个**从浏览器里复制的真实 URL** 做测试样例：普通岗位页、带追踪参数、带 `/apply` 后缀、岗位列表页（应返回 `null`）
  - 留意：Greenhouse 有新旧两个域名和一个嵌入页格式，三种都要有样例

- [x] **M1.4 解析器：其余五家**（3h）
  - 做：按同样方式补上 Ashby、SmartRecruiters、Workable、iCIMS、Workday
  - 验收：每家至少 4 个真实 URL 样例，全部通过；同一岗位的不同 URL 变体解析出相同的 `(ats, company, jobId)`
  - 留意：Workday 最麻烦。路径里有可选的语言段（如 `/en-US/`），岗位 ID 在最后一段的 `_` 之后，申请流程中 URL 还会追加 `/apply/...`。多找几家公司的链接对比

- [x] **M1.5 存储封装**（1h）
  - 做：在 `lib/types.ts` 里补上 `Settings` 类型；`lib/store.ts`：`getJob(key)`、`saveJob(record)`、`deleteJob(key)`、`listJobs()`、`getSettings()`、`saveSettings()`。每条记录单独一个存储 key（`job:<key>`），设置放在 `settings`，带默认值
  - 验收：在扩展后台的开发者工具控制台里手动调用，能写入、读出、删除；`listJobs()` 不会把 `settings` 当成记录返回

- [x] **M1.6 内容脚本最小闭环**（1h）
  - 做：内容脚本只匹配七家 ATS 的域名；页面加载后解析当前 URL，解析成功就写入一条 `viewed` 记录，失败就什么都不做。此时还没有任何界面
  - 验收：打开一个真实的 Greenhouse 岗位页，在开发者工具的扩展存储里能看到这条记录；打开岗位列表页不产生记录
  - 留意：检查生成的 manifest，确认主机权限只有这七家的域名

- [x] **M1.7 弹框骨架**（2h）
  - 做：`lib/toast.ts`，用 Shadow DOM 在页面右上角挂一个弹框，支持传入标题、正文、若干按钮；带关闭按钮；不自动消失，点 × 或离开页面才消失；没有动画。先用写死的内容测试
  - 验收：在 Greenhouse、Lever、Workday 三个页面上外观一致，不被页面自身的 CSS 影响；Tab 键能聚焦到按钮
  - 留意：同一页面重复调用时先移除旧弹框，保证最多只有一个

- [x] **M1.8 自动模式：首次访问**（1.5h）
  - 做：首次打开岗位页 → 写入 `viewed` → 弹框显示"已记录"，带 **撤销**（删除这条记录）和 **标记已申请**（状态改为 `applied` 并写入 `appliedAt`）
  - 验收：三个动作各试一遍，每次都去存储里核对结果

- [x] **M1.9 重复提醒**（1h）
  - 做：打开已有记录的岗位页 → 更新 `lastSeenAt` → 弹框显示"你在某日看过 / 申请过这个岗位"。状态是 `viewed` 时带 **标记已申请**，是 `applied` 时不带
  - 验收：从两个不同的聚合平台点进同一个岗位（URL 的追踪参数不同），第二次能认出来。这是整个项目的核心场景

- [x] **M1.10 手动模式**（1h）
  - 做：读取设置里的 `mode`。手动模式下首次访问不自动写入，弹框询问"是否记录"，带 **记录** 和 **忽略**；重复提醒的行为与自动模式相同
  - 验收：设置界面还没做，先在后台控制台里直接改存储中的 `mode` 来切换；两种模式各走一遍
  - 留意：忽略不落库，下次打开仍会询问

- [ ] **M1.11 单页应用内跳转**（1.5h）
  - 做：监听 URL 变化（WXT 提供了路由变化事件），变化后重新执行"解析 → 查库 → 弹框"；URL 变成非岗位页时关闭旧弹框
  - 验收：在 Workday 和 Ashby 的岗位列表里连续点开三个岗位，每个都正确触发一次，不重复、不遗漏
  - 留意：同一个岗位的 URL 只是参数变化时不应重复弹框，用解析出的 key 而不是原始 URL 来判断"是否换了岗位"

- [ ] **M1.12 提取岗位标题和公司名**（1.5h）
  - 做：按顺序回退：页面内的 JSON-LD `JobPosting` → `og:title` / `og:site_name` → `document.title` → URL 里的公司标识。写入记录并显示在弹框里
  - 验收：七家 ATS 各打开一个岗位，记下每家实际命中的是哪一层，把结果补到需求文档 1.5.1
  - 留意：单页应用里这些标签可能晚于脚本执行才出现，需要等一下再读；JSON-LD 内容可能格式不合法，解析要包在异常处理里

- [ ] **M1 收尾：自用三天**
  - 做：正常投简历，把遇到的问题记下来（没识别的 URL、误判成同一岗位、弹框挡住内容等）
  - 验收：问题清单整理完，决定哪些在 M2 之前修

## M2 关键词预警与设置（约 6.5 小时）

- [ ] **M2.1 关键词扫描纯函数**（2h）
  - 做：`lib/keywords.ts`：`scan(text, rules)` 返回命中列表，每项包含类别和**命中处所在的原句片段**；内置三类默认规则（见需求文档 1.6）
  - 验收：每类规则至少 3 个应命中的句子和 3 个不应命中的句子做测试。必须包含这一对：`We are unable to sponsor visas`（命中）和 `We sponsor visas for qualified candidates`（不命中）
  - 留意：同一类别命中多处时只保留前一两处，避免弹框过长

- [ ] **M2.2 等内容渲染完再扫描**（1h）
  - 做：页面 DOM 在一小段时间内不再变化后，取页面文本扫描一次；设一个总超时，超时就用当时的内容扫
  - 验收：在 Workday（内容加载最慢）上能扫到 JD 正文里的关键词；每个岗位页只扫一次

- [ ] **M2.3 预警并入弹框**（1h）
  - 做：记录信息和预警合并在同一个弹框里分区显示；命中的类别写入记录的 `flags`
  - 验收：找一个真实的要求 clearance 的岗位，弹框显示类别和原句；存储里 `flags` 正确
  - 留意：预警晚于记录信息出现时，应更新已有弹框而不是再弹一个

- [ ] **M2.4 设置数据层**（0.5h）
  - 做：`Settings` 补全：`mode`、`keywordsEnabled`、`rules`。内容脚本每次执行时读取；预警开关关闭时跳过扫描
  - 验收：在控制台里关掉开关后不再出现预警

- [ ] **M2.5 Dashboard 外壳与设置页**（2h）
  - 做：新建 dashboard 页面入口（React），先只做"设置"一个标签页：模式切换、预警开关、规则的增删改、恢复默认规则
  - 验收：改完设置后刷新一个岗位页，行为立即跟着变
  - 留意：用户输入的正则可能不合法，保存前要校验并提示；内容脚本遇到非法规则应跳过，不能整个报错

## M3 Dashboard 与 Popup（约 16 小时）

- [ ] **M3.1 打开 dashboard 的通路**（0.5h）
  - 做：background 监听一条"打开 dashboard"消息并新开标签页；弹框里加一个入口
  - 验收：在岗位页的弹框里点一下能打开 dashboard
  - 留意：background 只做这一件事，保持极薄

- [ ] **M3.2 Popup**（2h）
  - 做：替换模板 popup。显示当前标签页的状态（未记录 / 看过 / 已申请）；按钮：**记录当前页面**、**标记已申请**、模式切换、**打开 Dashboard**
  - 验收：在一个不属于七家 ATS 的招聘页上点"记录当前页面"，生成一条 `ats = other` 的记录；再次打开 popup 显示"看过"
  - 留意：通过 `activeTab` 权限获取当前页 URL，不要为此申请 `tabs` 权限

- [ ] **M3.3 Dashboard 数据加载**（1h）
  - 做：页面加载时读取全部记录；监听存储变化，其他标签页产生新记录时自动刷新
  - 验收：开着 dashboard，在另一个标签页打开新岗位，dashboard 无需刷新就出现这条记录

- [ ] **M3.4 记录列表**（1.5h）
  - 做：表格，列为日期、公司、岗位标题、ATS、状态、预警标签、链接；默认按最近访问时间倒序，点击表头可切换排序
  - 验收：有 20 条以上真实记录时显示正常；没有记录时有空状态提示

- [ ] **M3.5 搜索与筛选**（1.5h）
  - 做：搜索框（匹配公司和标题）；按状态、ATS、预警类别筛选
  - 验收：筛选条件可叠加；清空条件后恢复全部

- [ ] **M3.6 行内操作**（2h）
  - 做：切换状态（`viewed` ↔ `applied`，同步维护 `appliedAt`）；删除（需二次确认）；编辑公司名和标题
  - 验收：每个操作后刷新页面，结果仍在

- [ ] **M3.7 添加 URL**（1h）
  - 做：顶部"添加 URL"输入框，可选择直接标记为已申请。走 `parseJobUrl`，解析不了就用规范化 URL 作 key
  - 验收：添加一个已存在的岗位 URL 时提示"已存在"而不是覆盖；输入不是 URL 的内容时有错误提示

- [ ] **M3.8 数量统计**（1.5h）
  - 做：一排统计卡片：累计看过、累计申请、近 7 天申请、看过→申请转化率；按 ATS 分布的条形图（用 div 按百分比设宽度）；命中各类预警的岗位数
  - 验收：手工数一遍记录，和卡片数字一致

- [ ] **M3.9 每日活跃度热力图**（2.5h）
  - 做：最近一年的格子图，一列一周，颜色深浅按当天 `appliedAt` 的数量分 4–5 档；悬停显示日期、申请数、浏览数
  - 验收：今天申请一个岗位，今天的格子颜色变化；跨年、跨月的位置正确
  - 留意：按**本地时区**的日期归类，不要直接用 UTC，否则晚上投的会算到第二天

- [ ] **M3.10 导出**（1h）
  - 做：导出 JSON（全部记录加设置，带版本号字段）；导出 CSV（只含记录）
  - 验收：CSV 用 Excel 或 Numbers 打开列对齐；标题里含逗号、引号的记录不串列

- [ ] **M3.11 导入**（1.5h）
  - 做：导入 JSON。逐条校验字段，不合法的跳过并统计数量；与现有记录 key 相同时合并：`firstSeenAt` 取较早的，状态以 `applied` 为准
  - 验收：导出 → 清空扩展数据 → 导入，数据完全恢复；导入一个随便写的 JSON 文件不会破坏现有数据，并给出错误提示

## M4 发布（约 9.5 小时）

- [ ] **M4.1 Firefox 跑通**（2h）
  - 做：用 Firefox 开发模式启动；在配置里补上 Firefox 需要的扩展 ID 和数据收集声明（填"不收集"）；把 M1–M3 的验收项在 Firefox 里过一遍
  - 验收：记录、提醒、预警、popup、dashboard、导入导出在 Firefox 里全部正常
  - 留意：Chrome 导出的 JSON 能在 Firefox 里导入，这是用户换浏览器的唯一迁移方式

- [ ] **M4.2 名称与图标**（1h）
  - 做：定一个有辨识度的名字（先在两个商店里搜一下是否重名）；准备 16 / 32 / 48 / 128 像素图标
  - 验收：工具栏和扩展管理页里图标清晰

- [ ] **M4.3 持续集成**（1h）
  - 做：GitHub Actions：每次推送运行测试，并分别构建 Chrome 和 Firefox 版本
  - 验收：故意改坏一个解析器测试，CI 变红

- [ ] **M4.4 README**（2h）
  - 做：中英双语。内容：一句话说明解决什么问题、演示 GIF（展示"从两个平台点进同一岗位被认出来"）、支持的 ATS 列表、隐私声明（零网络请求、数据只在本地）、卸载会丢数据的提醒、本地开发步骤
  - 验收：找一个没听过这个项目的人看 30 秒，能说出它是干什么的

- [ ] **M4.5 打包检查**（0.5h）
  - 做：生成 Chrome 和 Firefox 的发布包以及 Firefox 审核用的源码包
  - 验收：把生成的包解压后以未打包方式加载，功能正常；包里没有测试文件和多余内容

- [ ] **M4.6 提交 Chrome Web Store**（1.5h）
  - 做：注册开发者账号（一次性 5 美元）；填写商品详情、截图、隐私实践表单；逐条说明每个权限的用途
  - 验收：提交成功，进入审核

- [ ] **M4.7 提交 Firefox AMO**（1h）
  - 做：上传发布包和源码包，填写构建步骤说明
  - 验收：提交成功，进入审核

- [ ] **M4.8 发布 v1.0.0**（0.5h）
  - 做：打 git tag，创建 GitHub Release 并附上两个发布包；商店上架后把链接补进 README
  - 验收：从商店全新安装一遍，走通首次记录和重复提醒
